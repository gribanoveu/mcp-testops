  скрытого вручную результата: без него два прогона одного теста выглядят как два разных теста.
  Второе — значения параметров: только они отличают две строки с одинаковым именем.

  значение обязательно и что оно из списка.

  `sharedStep: {id, name, steps}`, собранный из `sharedSteps` + `sharedStepScenarioSteps`. Проверено на

Исправлено по итогам стенда:

- **`add_test_result` без `test_case_id` падал с `500`** — `testCaseId` обязателен, хотя схема его не

## 2026-11-09 — npm через trusted publishing

- `NPM_TOKEN` в секретах отвалился (`E401`), и это хороший повод убрать его совсем: npm-публикация
  идёт через trusted publishing (OIDC). Job просит `id-token: write`, токен короткий и выдаётся
  раннеру на время прогона — нечему истекать и нечего утечь.
- `registry-url` у `setup-node` убран намеренно: он пишет `_authToken` в `.npmrc`, и npm тогда идёт по
  токенному пути вместо OIDC. `NODE_AUTH_TOKEN` из шага тоже убран — даже пустой он ломает OIDC.
- Схема осталась staged: `npm stage publish` в CI, одобрение мейнтейнером с 2FA.
